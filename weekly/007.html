第7回 2026年7月12日（日） 🔧 AI活用

Cursorで過去MR指摘と現在の修正を
自動照合する仕組みを作った

Cursor GitLab AI活用 レビュー 品質改善

📌 今回取り上げたもの

過去のMRレビューで受けた指摘と、現在作業中の修正内容を自動的に照合するツールをCursorとGitLab APIを組み合わせて作成した。

📝 仕組みの概要

GitLab APIを使って複数リポジトリ・複数MRのレビューコメントを収集し、past_feedback.md として書き出す。これをCursorのルールファイル（.cursor/rules/）に登録しておくことで、コード編集中にCursorが過去の指摘を常時参照して照合してくれる仕組みになっている。

1
GitLab API でコメントを収集
自分がAuthorのMRから全体コメント・インラインコメントを両方取得。複数リポジトリを横断。
↓
2
past_feedback.md に書き出し
MR・レビュアー・コメント本文を Markdown 形式で整理して保存。
↓
3
Cursor ルールとして登録
コード編集のたびに past_feedback.md を参照して照合するよう Cursor に指示する。
↓
4
照合結果を出力
「抵触なし / あり」に加え、抵触はしていないが過去指摘に近い箇所を「念のための確認ポイント」として提示。根拠となった過去コメントも引用される。
✅ 結果: 過去指摘との抵触なし
⚠️ 念のための確認ポイント（3件）
  • public/ 更新あり → MR説明に検品URLを明記すると安心
  • scss/pug変更あり → VRTまたは画面確認の証跡をMRに残す
  • ABテスト系ファイルへの注意コメント追加 → 既存方針と整合

また、同ファイルを使って過去指摘のグルーピング分析も実施した。下記は実際に出力された苦手傾向（対象2MR・サンプル数23件）の一例。

💡 自分の考え・業務への活用案

現在抱えている課題の一つとして、同じ指摘を繰り返し受けてしまうという点がある。「以前言われたから気を付ける」は至極当然のことだが、それができないから課題になっている。人力だとチェックが漏れてしまったり、そもそも過去の指摘を覚えていない限りすべての指摘をさかのぼるのに莫大な時間がかかる可能性がある。ただでさえ期日がある案件対応などにおいて、人力チェックには限界があるように感じた。

そこで、業務で使用するCursorを活用し、過去の指摘と今回の修正内容の照合ができないかという点を検討してみた。結果、複数リポジトリの指摘を横断的に参照可能ということもあり、すべて覚えることや直前に全部網羅しなければという時間的負担を減らせそうであると感じた。出力結果としては、抵触部分のチェックはもちろん、抵触していなくても過去の指摘に近い箇所を「念のための確認ポイント」として提案してくれる。提案の際には具体的な過去の指摘も挙げてくれるので、対応案が今回の案として正しいかの判断も検討しながらチェックできるという点も強いと感じた。

また、指摘内容はファイルに格納するようになっているので、このファイルの中身を使用すれば別のチェックへの汎用が可能だと考えられる。例えば、指摘のグルーピングによる苦手傾向の分析などが挙げられる。実際にやってみたが苦手傾向ごとの出現頻度や注意すべき点を挙げてくれるので、無意識に飛ばしがちな点を定期的にチェックしやすい点に加え、急遽振り返る必要が出た時にすぐ確認できる点もよいと感じた。

改善点としては、現状は作業プロジェクトのルートにルールファイルを置く方式になっているが、CursorのグローバルルールとしてSettings → Rules for AIに設定すれば、全プロジェクトで自動的に反映されるようになる。今後はその方向で設定を整えていきたい。
