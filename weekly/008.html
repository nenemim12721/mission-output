CursorでGitLabのMRを
自動生成する仕組みを設計した

Cursor GitLab MCP AI活用 自動化

📌 今回取り上げたもの

GitLabのマージリクエスト（MR）をCursorから自動生成できる仕組みの設計を行った。MR作成時のテンプレートコピペや手入力の手間を省くことが目的。実践は後日行う予定のため、今回は設計と方針の整理まで。

📝 設計概要：2つのアプローチ

今回、実現方法として2つのアプローチを検討した。

方式A｜GitLab MCP × Cursor（自然言語操作）

@modelcontextprotocol/server-gitlab をCursorのMCPとして接続し、チャットから自然言語でMRを作成する方法。テンプレートはCursorのルールファイルに書いておき、依頼時に参照させる。

1
.cursor/mcp.json にGitLab MCPを設定
トークンと社内GitLabのAPIベースURLを環境変数として渡す。
↓
2
.cursor/rules/ にMR説明文テンプレートを登録
概要・変更内容・確認方法・チェックリストなどをルールファイルとして書いておく。
↓
3
Cursorチャットで「MR作って」と依頼
テンプレートを参照させ、タイトル・target branchを指示するだけでMCPがAPIを呼ぶ。
↓
4
GitLab上にMRが自動生成される
作成されたMRのURLがチャットに返ってくる。
.cursor/mcp.json の設定例
{ "mcpServers": { "gitlab": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-gitlab"], "env": { "GITLAB_PERSONAL_ACCESS_TOKEN": "your-token", "GITLAB_API_URL": "https://your-gitlab.example.com/api/v4" } } } }

方式B｜Node.jsスクリプト（直接API呼び出し）

GitLab REST APIを叩くスクリプトを作成し、ターミナルから実行する方法。前回の fetch_past_feedback.mjs と同じ構成で、MR作成に特化したスクリプトを追加する。

1
案件テンプレートMDからタイトルを自動取得
プロジェクトに置いてある案件テンプレートファイルからMRタイトルを抽出する。
↓
2
現在のブランチ名を自動取得（source_branch）
git rev-parse --abbrev-ref HEAD で現在のブランチを取得。
↓
3
--target 引数でマージ先ブランチを指定
develop / main など状況によって切り替えられるよう引数で受け取る。
↓
4
GitLab API POST /merge_requests を実行
template.md を読み込んで description に使用。作成されたMRのURLを出力。
呼び出し例
node tools/create_mr/create_mr.mjs --target develop node tools/create_mr/create_mr.mjs --target main

2方式の比較

観点 MCP方式 スクリプト方式
操作感 チャットで自然言語 ターミナルでコマンド
レビュアー・ラベル指定 ✗ MCPが未対応 ✅ 自由に設定可
タイトル自動取得 Cursor Agentに依存 ✅ MD から自動抽出
拡張性 MCPの機能範囲内 ✅ 制限なし
社内申請 MCPの利用申請が必要 不要
