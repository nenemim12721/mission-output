Cursorのデザイン実装の
再現度を上げるためにやるべきことを調べた

Cursor Figma MCP デザイン実装 フロントエンド

📌 今回取り上げたもの

CursorでFigmaデザインを実装する際、再現度が満足いくレベルに達しないことが課題としてある。「どうすれば再現度が上がるか」を2つの視点で調査した。①Figmaのデザインデータ構造そのもの、②Cursorへの指示方法・事前設定。実践は次回出勤時に行う予定で、今回は調査と方針整理まで。

🗂 ① Figmaのデータ構造が再現度を左右する

Figma MCPがCursorに渡せる情報の質は、Figmaファイルの設計品質に直結する。どれだけCursor側の設定を整えても、Figmaが整っていなければ再現度は上がらない。

再現度が上がるFigmaの条件

  • ✓Auto Layoutを使う — レイアウト制約が構造データとしてMCPに渡される。使われていないと意図が伝わらない
  • ✓レイヤーを論理的にグルーピング＆命名 — 「Group 5」ではなく「CardContainer」のような命名でAIがコンポーネント構造を正しく解釈できる
  • ✓デザイントークン（変数）を使う — 色やスペーシングを直打ちせず変数化することでMCPが --color-primary として渡せる
  • ✓Constraintsを設定する — レスポンシブの挙動がAIに伝わる
  • ✓レイヤーを重ねない — 重複レイヤーがあるとAIが構造を誤解する

使わない方がいい状況

  • ✗レイヤーが混沌としていて命名が不整合なとき
  • ✗色・テキストスタイルが変数化されていないとき
  • ✗Auto Layoutが使われていないとき

「Figmaがぐちゃぐちゃな状態でMCPを使っても、手動でやるより修正に時間がかかるだけになる」（ByteMinds）

⚙️ ② Cursorの設定・指示方法で再現度を上げる

A. スクリーンショットではなくFigma MCPで渡す（最大の効果）

手法 AIが受け取る情報 精度
スクリーンショット貼り付け 見た目のみ 低
Figma MCP接続 ノードツリー・制約・トークン・アセット参照 高（修正イテレーション50〜70%削減の報告あり）

B. 2段階取得フロー（コンポーネント単位でも止まる場合の対策）

コンポーネント1つでもネストが深いと止まることがある。Figma公式が推奨する2段階フローをCursor Rulesに書いておくことで自動的に対応できる。

1
get_design_context を実行
まずコンポーネント全体の構造データを取得する。
↓ レスポンスが大きすぎる・途中で切れた場合
2
get_metadata でノードマップを取得
全体ではなく「骨格の概要」だけを先に取得する。
↓
3
必要なノードだけを get_design_context で再取得
骨格から対象を特定して、その部分だけを深掘りする。
↓
4
get_screenshot でビジュアル参照を取得してから実装
構造データとビジュアル参照の両方が揃った状態で実装を開始する。

C. Cursor Rulesに書いておくと効果が高いこと

## Required flow (do not skip) 1. Run get_design_context first. 2. If the response is too large or truncated, run get_metadata to get the high-level node map, then re-fetch only required nodes with get_design_context. 3. Run get_screenshot for visual reference. 4. Only after both, download assets and start implementation. ## Color & Design System - Extract exact colors from Figma data; do not approximate. - Use exact hex or rgba values; do not approximate with Tailwind. - Create CSS variables in src/index.css for brand colors. ## CSS / Styling - Use mobile-first approach. - Prefer flexible dimensions over fixed ones.

※ Rulesは150行以内に収めるとAIの遵守精度が落ちにくい。重要な指示はプロンプトにも直接書く。

D. プロンプトはコンポーネント単位＋詳細指示

@feature.tsx Implement the component design from https://www.figma.com/design/<link> according to the @always.md. Use Tailwind for layout, spacing and typography. Do not download images. Use placeholders from @images.

ページ全体を一度に渡さずコンポーネント単位で渡す。詳細プロンプトにすることでAIの余計な判断を減らせる。

❓ 調査中に出てきた疑問点と回答

Q1. プロンプトは日本語だと精度が下がる？
下がる傾向はある。ArXivの研究（2025年）によるとコーディングタスクで英語76.2% → 非英語平均61.1%という差が確認されている。ただしCursorが使うモデル（Claude・GPT-4o等）は多言語対応しており日本語でも実用的。Cursor Rulesや技術的に重要な指示は英語で書いた方が精度が高くなりやすい。
Q2. コンポーネント単位で渡しても途中で止まる場合は？
コンポーネントの内部ネストが深いと1つでもコンテキスト上限を超える。対策は上記「B. 2段階取得フロー」の通り。get_metadata → get_design_context の順で取得することで、必要な部分だけを渡せる。このフローをCursor Rulesに書いておけば自動的にたどってくれる。また、Figma APIのレート制限（429エラー）で止まる場合はセッションの切断・再接続で解消することが多い。
Q3. フロントエンジニア側でできることはあるか？
最も効果が高いのは CSS変数名をFigmaのトークン名と1:1で対応させること。Figma MCPはトークン名で変数を解決するため、名前が一致していないと生の値（#2563EBなど）にフォールバックしてしまう。「CSSが変数でなくべた書きになる」問題の根本原因はここにある。また、html・body・フォント・ブレークポイントなどの基本設定を自分で書いておき、その上でAIにFigmaから値を引っ張らせる方がコントロールしやすい。

📋 結論：再現度を上げる優先順位

最優先
Figmaファイルを整理する（Auto Layout・変数・命名） — 土台が整っていないと他の対策が効かない
最優先
CSS変数名をFigmaトークン名と1:1で対応させる — 「べた書きになる」問題の根本解決
高
Figma MCPを接続する — スクリーンショット渡しをやめる。修正イテレーションが大幅に減る
高
Cursor Rulesに2段階取得フロー＋スタイル指示を書く — 150行以内で、毎回プロンプトに書かなくて済む
中
プロンプトを詳細に書く — コンポーネント単位＋Figmaリンク＋ルール参照の形式で
中
重要な指示は英語で書く — プロンプト・Rulesともに英語の方がモデルの遵守精度が高い
