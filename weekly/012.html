第12回 2026年8月14日（金） 📚 ナレッジ連携

Confluenceの用語集ページと
Cursorを連携させる仕組みを設計した

Cursor Confluence MCP ナレッジ連携 AI活用

📌 今回取り上げたもの

第10回の「自分の考え」で触れた「案件Confluenceの用語集ページと連携できれば、案件内容の理解をさせやすくなるのでは」というアイデアを、実際の検証設計まで落とし込んだ。案件特有の用語（略称・社内呼称など）をAIが正しく理解できていないと、指示の解釈がずれて手戻りが起きやすい。この仮説を検証する仕組みを今回設計した。実践はまだ行っていないため、今回は設計と方針整理まで。

🔌 ① Atlassian公式MCPサーバーで実現できること

ConfluenceをCursorに接続する方法を調べたところ、Atlassian公式が提供するリモートMCPサーバー（Jira・Confluence・Bitbucketを1つの設定でまとめて扱える）が有力な選択肢として見つかった。

  • ✓ページ検索 — キーワードから該当するConfluenceページを検索できる
  • ✓ページ取得＋Markdown変換 — Wikiコンテンツを読み込みAIが扱いやすい形式に変換する
  • ✓特定ページの参照 — プロンプト内で対象ページを直接指定して読み込ませられる
  • ✓要約・分析 — 取得した内容をもとにAIが要約・関連付けを行える

GitLab MCPがPersonal Access Token方式だったのに対し、Atlassian公式MCPはOAuth連携が前提になっている点が異なる。

⚙️ ② 想定するセットアップ

1
Atlassian公式MCPをOAuth連携
社内Confluenceのワークスペースに対してOAuth認証を行う。トークンを直接扱う必要がない。
↓
2
.cursor/mcp.json に設定を追加
MCPサーバーのエンドポイントをCursorの設定に登録する。
↓
3
案件用語集ページのIDを控えておく
対象の用語集ページを特定できるようにし、参照時に迷わないようにする。
↓
4
Cursor Ruleに参照条件を明記
案件特有の用語が出てきた際に、用語集ページを自動参照するようルール化する。
.cursor/mcp.json の設定イメージ
{ "mcpServers": { "atlassian": { "url": "https://mcp.atlassian.com/v1/sse" } } }

※ OAuth認証のため、初回接続時にブラウザでの認可フローが発生する想定。実際の値は導入時に要確認。

📝 ③ Cursor Ruleの設計案

第10回で整理した4カテゴリでいうと、この用語集参照ルールは「マイクロワークフロー」に近い。常時読み込む必要はなく、案件特有の用語が話題に出たときだけ自動適用させたいため、Agent Requestedで設計するのが適切だと考えている。

📄 .cursor/rules/confluence-glossary.mdc（設計イメージ）
--- description: "案件特有の用語・略称が話題に出た際に、Confluenceの用語集ページを参照して正しい定義を確認する" --- ## 用語集参照ルール - 案件特有の用語・略称・社内呼称が出てきた場合、 推測で処理せずConfluence MCPで用語集ページを参照すること - 参照した用語の定義が既存の理解と異なる場合、 その旨をチャットで明示すること

⚠️ 注意点・限界

Pull型であり、自動同期ではない。Cursorが自発的に更新を検知するわけではなく、都度リクエストした時点の内容しか取得できない。用語集ページが更新されても、次にAIが参照するまでは古い定義のまま処理される可能性がある。

OAuth連携の社内申請が必要になりそう。GitLab MCPのPAT方式と異なり、ワークスペース単位の認可が必要なため、導入には情シス側の許可が必要になるケースが多いと考えられる。
